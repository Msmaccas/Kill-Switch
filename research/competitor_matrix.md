# Competitor Matrix – persistent-memory trading agents, finance workspaces & reporting‑integrity tools

This matrix summarises the landscape of systems that are closest to the planned **KillSwitch** product.  Only current information from official documentation, release notes, academic papers and repository read‑mes is used (accessed May 31 2026).  The goal is not to produce an exhaustive list of all agent frameworks; rather, it focuses on three niches relevant to KillSwitch:

1. **Multi‑agent trading frameworks with persistent memory or decision logs** – these systems coordinate specialised agents, maintain decision history and support resumption or re‑entry into a workflow.
2. **Finance workspaces with agent integrations** – these products turn AI agents into persistent, collaborative environments where context and data persist across sessions.
3. **Tools that detect reporting inconsistency or contradiction** – research and products that automatically identify discrepancies or contradictions in financial or compliance documents.

Each subsection below provides a short narrative description followed by a table with key features.  Long explanations stay in the paragraphs; tables use concise phrases and numbers.

## Multi‑agent trading frameworks

### TradingAgents (Tauric Research)

TradingAgents is a LangGraph‑based multi‑agent LLM trading framework that simulates a professional trading firm.  The framework decomposes the trading process into specialised roles—fundamental, sentiment, news and technical analysts, bull and bear researchers, traders with different risk profiles, risk managers and a portfolio manager【146374486905844†L19-L48】.  Its v0.2.4 release notes highlight several key capabilities: (1) **structured output decision agents** via Pydantic schemas so that decisions are typed rather than free‑form text; (2) **LangGraph checkpoint resumption** that persists per‑node state in `~/.tradingagents/cache/checkpoints/<TICKER>.db`, allowing runs to be resumed without re‑processing previous steps【794684507694247†L98-L116】; (3) **persistent decision memory** stored in `~/.tradingagents/memory/trading_memory.md` which appends each run’s decision, realized return and a retrospective, and automatically injects this history into future prompts【794684507694247†L110-L124】; (4) a **5‑tier rating system** for portfolio manager decisions and integration with multiple LLM providers【794684507694247†L120-L142】.  The framework’s initial public release (v0.1.0) already included per‑agent BM25 memory to retrieve past observations【735177709479739†L630-L634】.  While TradingAgents shows strong multi‑agent design, it currently treats decision logs as simple append‑only markdown files; there is no built‑in system for explicitly defining thesis kill‑conditions or tracking the reasons behind an entry.

### AlphaCrafter (Nanjing University)

AlphaCrafter is an academic full‑stack multi‑agent framework for **cross‑sectional quantitative trading**【196504147709959†L71-L100】.  Unlike role‑playing anthropomorphic designs, AlphaCrafter uses three agents—**Miner**, **Screener** and **Trader**—to create a closed‑loop factor‑to‑execution pipeline.  All agents share a **common memory** that serves as a central conduit for historical observations, factor validation outcomes and execution feedback【196504147709959†L210-L217】.  This shared memory is persisted via periodic summarisation: after each run, agents propagate performance diagnostics, enforce consistency constraints and relay conditional guidance to downstream decisions【196504147709959†L210-L217】.  The Miner avoids redundant exploration by referencing memory during factor generation【196504147709959†L230-L237】 and records validation outcomes for later runs.  The Screener updates memory with the composition of factor ensembles and market regime assessments【196504147709959†L258-L267】, while the Trader writes execution feedback back to memory【196504147709959†L297-L299】.  AlphaCrafter focuses on quantitative factors and risk‑constrained execution rather than thesis reasoning, and it lacks a user‑facing dashboard or explicit thesis invalidation logic.

### vibe‑trading‑ai

Vibe‑trading‑ai is an open‑source Python/CLI tool designed as a **personal trading agent and research workspace**.  It connects natural‑language prompts to market data loaders, strategy generators, backtest engines and persistent research memory【606789568516202†L340-L364】.  The project emphasises **persistent memory**, which is inspectable via CLI commands like `vibe‑trading memory list/show/search/forget` and supports international text【606789568516202†L141-L144】.  Its “repeated research” workflow uses **persistent memory and editable skills** to turn successful routines into reusable workflows【606789568516202†L358-L360】.  The package ships **multi‑agent research teams** (75 finance skills across eight categories and 29 preset trading teams) that can conduct bull/bear debates, risk reviews, factor research and backtesting【606789568516202†L360-L475】.  It deliberately does **not execute live trades**【606789568516202†L340-L345】.  Vibe‑trading‑ai has no concept of thesis objects or kill‑switch conditions; it is aimed at research and backtesting rather than real‑time portfolio management.

### CrewAI with cognitive memory

CrewAI is a general multi‑agent orchestration framework.  A recent blog post details the new **cognitive memory system**, which treats memory as an **active cognitive process** rather than passive storage【488358425648626†L22-L40】.  The system encodes selectively, consolidates facts, detects contradictions and forgets purposefully【488358425648626†L70-L83】.  Five operations—`remember`, `recall`, `extract`, `tree` and `forget`—expose this behaviour【488358425648626†L94-L139】.  Turning memory on in a Crew automatically loads and persists memories across tasks so agents can recall context and store what they learn【488358425648626†L94-L105】.  CrewAI is not specific to trading; however, its cognitive memory shows how multi‑agent systems can maintain shared context, detect contradictions and evaluate retrieval confidence, which are all relevant to KillSwitch’s design.

## Finance workspaces with agent integrations

### Taskade – Agentic Workspace (Workspace DNA)

Taskade markets the concept of an **agentic workspace**, described as a persistent AI environment where memory, agents, automation and collaboration form a self‑reinforcing loop【942631209110490†L344-L366】.  In Taskade’s **Workspace DNA** architecture, memory feeds intelligence, intelligence triggers execution and execution creates memory【942631209110490†L351-L355】.  Projects store structured knowledge (memory), AI agents reason over that context, and automations trigger actions【942631209110490†L379-L475】.  Agents support persistent memory, multi‑model selection and custom tools; they can be embedded publicly or trained on private documents【942631209110490†L443-L445】.  Taskade emphasises 100+ integrations for execution and positions agentic workspaces as durable systems that continue working after a prompt disappears【942631209110490†L344-L347】.  While Taskade is not finance‑specific, it illustrates how workspace‑level memory and automation could underpin persistent thesis monitoring.

Although not a trading execution platform, its persistent memory and agent integrations make it a relevant benchmark for thesis‑tracking dashboards.

## Reporting‑integrity and contradiction‑detection tools

### Lyzr AI agents for compliance

Lyzr provides AI agents for compliance teams that automate tasks such as policy enforcement, regulatory monitoring and audit preparation.  The product emphasises three features relevant to KillSwitch: **automated reporting**, **workflow orchestration** and **explainable logs**.  Agents generate structured compliance reports aligned to regulator formats【140125026040166†L283-L287】 and coordinate multi‑step compliance tasks across the enterprise【140125026040166†L287-L290】.  Every agent action is logged with clear reasoning, producing a comprehensive and unified audit trail【140125026040166†L291-L334】.  Lyzr claims to provide adaptive, real‑time policy enforcement and continuous regulatory adaptation【140125026040166†L311-L327】.  Although focused on regulatory compliance rather than trading, its explainable logs and automatic report generation demonstrate mechanisms for reporting‑integrity and auditability.

### Deep‑learning detection of disclosure discrepancies

Research published in the *Journal of Sustainability, Policy and Practice* presents a deep‑learning approach for **detecting disclosure discrepancies in SEC filings**【424101890780319†L50-L68】.  The system combines a Transformer‑based discrepancy classifier with rule‑based validation to identify numerical contradictions, formatting irregularities and narrative inconsistencies across 10‑K and 10‑Q filings【424101890780319†L52-L64】.  It achieved 94.3 % accuracy on cross‑period discrepancies and reduced manual review time by 67 %【424101890780319†L63-L69】.  While not a multi‑agent framework, the research illustrates automated detection of reporting inconsistencies and could inspire kill‑condition triggers in KillSwitch.

### ContraGen – contradiction‑aware multi‑agent benchmark

ContraGen is a research framework that creates **synthetic enterprise documents with embedded contradictions** to benchmark retrieval‑augmented generation systems【20300797525322†L31-L50】.  Its architecture includes a **contradiction‑aware content generation agent**, a **contradiction mining agent** and a **retrieval verifiability agent**【20300797525322†L29-L47】.  The goal is to evaluate whether RAG pipelines can detect and resolve self‑ and cross‑document contradictions【20300797525322†L43-L50】.  ContraGen does not provide a ready‑made product, but it highlights the need for contradiction detection when generating or summarising enterprise documents, including financial reports.

## Observations for KillSwitch design

* **Persistent memory and decision logs are now common in multi‑agent trading frameworks.**  TradingAgents’ decision memory and checkpoint resumption, AlphaCrafter’s centralised shared memory and vibe‑trading‑ai’s persistent research memory all show the value of capturing past reasoning and execution outcomes.  However, these systems rarely enforce **explicit thesis kill‑conditions** or **ranked invalidation signals**.  They store decisions but don’t challenge them.
* **Agentic workspaces emphasise continuous operations.**  Taskade’s Workspace DNA concept and vibe‑trading‑ai’s workflow examples illustrate how memory, agents and automation can create living systems that persist beyond single prompts【942631209110490†L344-L355】.  These paradigms are compatible with KillSwitch’s need to run continuously in the background and monitor live market events.
* **Explainability and auditability are critical for regulatory contexts.**  Lyzr’s explainable logs, ContraGen’s contradiction taxonomy and the disclosure discrepancy detector all stress the importance of transparent reasoning and error detection【140125026040166†L291-L334】.  KillSwitch must therefore provide ranked explanations of why a thesis is drifting, not just silent alerts.
* **No existing tool enforces a thesis‑level kill switch.**  None of the reviewed systems explicitly model **thesis supports**, **kill conditions**, or **review cadence** with severity tiers (hard break, soft break).  This gap creates an opportunity for KillSwitch to differentiate by acting as a thesis memory and invalidation engine rather than a trading bot.
